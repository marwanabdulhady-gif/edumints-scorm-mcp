# Character bible and consistency

Choose characters for an instructional role: mentor, learner, colleague, customer or antagonist.
Record each ID, role, identity/appearance, visual style, invariant rules, required poses/expressions,
and a master reference asset ID. Specify clothing/PPE, age range, silhouette, proportions, palette,
lighting, camera angle, background/alpha and cultural context. Avoid stereotypes and unauthorized
real-person likenesses or voice cloning. Get explicit consent for client likeness/voice use.

Make one approved master reference before variants. Reference that same identity in each client
image tool request; preserve face, clothing and proportions. Plan individual manifest entries for
neutral, explaining, success, concern, hint, and any required interaction states. Each needs a
`character_id` and `variant`; the lint checks declared variants have planned assets.

Show character direction for approval before the full pack. Inspect consistency at course display
size and in context, not just as a large standalone image. Provide meaningful alt text unless truly
decorative. Record revisions and propagate a changed identity to affected variants/screens.

These are asset-production instructions, not a native character-animation runtime. For animated
characters use licensed footage or a client animation/video tool and import the rendered result.
